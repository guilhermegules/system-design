# Domain Driven Design

DDD is an approach of software development that centers the problems solving on a domain model that is rich and understand the own responsabilities and the bounds.

With this approach we create a language to communicate with non-technical people, [Ubiquitous Language](https://martinfowler.com/bliki/UbiquitousLanguage.html), 
and all the people is talking the same language we can model a better and more cohesive system.

The Eric Evans books introduces some classification for objects like, [Entities, Value Objects and Service Objects](https://martinfowler.com/bliki/EvansClassification.html) together with the concept of [Aggregates](https://martinfowler-com.translate.goog/bliki/DDD_Aggregate.html) that keep the domaing objects together.

Other big concept on DDD is the [bounded contexts](https://martinfowler-com.translate.goog/bliki/BoundedContext.html) that used to create a cluster of the domain entities and their bounds, working with bounded context teach us where the limits of the application contexts and how we create brides between the system parts.
